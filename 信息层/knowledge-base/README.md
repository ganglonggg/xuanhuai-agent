## 查询

无需安装依赖、配置模型或联网，使用 Python 3 标准库。在本目录运行：

```bash
python3 query.py '创业实战训练课怎么加入' --limit 3
python3 query.py '创业实战训练课去过哪些企业' --limit 3
python3 query.py '机器人方向的科创导师' --limit 3
python3 query.py '双周周二' --series '科创领导力'
python3 query.py '创业' --since 2026-11-01 --until 2026-11-15 --json
python3 query.py --facts
```

检索按系列别名、关键词、原文片段进行匹配，返回发布日期、来源链接和本地行号。它是证据检索工具，不是完整的对话 agent。关键词未命中不代表文章库一定没有答案；涉及当前时间的提问会附带当前发布库的核对范围提示，`--facts` 展示发布记录，`--facts --json` 返回完整结构。发布记录尚不按问题、日期或报名资格自动筛选，应结合 `verified_at` 与 `note` 使用；历史材料仅供背景参考。

### 添加人工核对记录

在 `人工核对记录.json` 的 `records` 数组中，为候选添加一条记录；`candidate_id` 必须来自 `data/fact-candidates.json`，同一 ID 只保留一条当前核对记录。更正现有确认时修改对应记录，再重新构建。示例结构：

```json
{
  "candidate_id": "candidate-docx-summary-0003-1",
  "title": "第四届致新班第二批招生及面试",
  "verdict": "对",
  "verified_fields": {"start_at": "2026-11-28"},
  "not_verified": ["面试具体时间", "location", "campus", "registration", "registration_deadline"],
  "verified_by": "Charles",
  "verified_at": "2026-11-15",
  "method": "对照来源后确认日期",
  "note": "只确认日期，具体时间和报名截止未确认。"
}
```

`verified_fields` 是“字段名 → 人工确认值”的非空对象，可覆盖候选原值，但字段必须存在于候选中，不能覆盖 ID、发布状态等系统字段。`verified_by`、`verified_at` 和 `note` 必填；`method` 可选。其他 verdict 不发布；已确认字段与 `not_verified` 不得重叠。核对记录中的 `title` 仅用于识别，若需确认标题，应明确写入 `verified_fields.title`。

输出的事实顶层仅包含已确认的业务字段及标识、来源和核对元数据，`verified_fields` 保留同一组确认值。`not_verified` 转为逐字段对象，每项包含候选原值 `value`、`verification_status: "未经人工确认"` 和 `present_in_candidate`；例如“面试具体时间”只出现在候选缺项清单中、并无对应字段，则保留为 `value: null`、`present_in_candidate: false`。未列入任一清单的业务字段不输出。`source.title` 等仅为来源元数据，不表示这些内容经过人工确认。

保存后在本目录运行上述构建和测试命令。构建可重复执行，确认记录不会被清空。两条现有记录只确认了课程日期／开始时间／地点或面试日期，**报名方式、截止日期和可报名状态未经人工确认**；使用时须保留 `note` 的范围限制。课表转录与下周草稿没有人工确认记录，不会因此进入发布库。

添加文章时，需新增稳定 ID、卡片、来源与证据，然后更新构建输入；当前尚未实现自动增量归档。图片由 AI 视觉检查，未经过人类核对；保留的图中文字尚未全部转录。原文音视频未转录。
