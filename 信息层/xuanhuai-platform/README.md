# 宣怀 agent · 本地验证版

无第三方依赖，Node.js 22+，仅监听 `127.0.0.1`。本轮打通按周课表、规则生成草稿、教师填写与确认、跨周关注和变更通知。需求卡与意向卡沿用原实现，本轮未修改 `lib/cooperation.js` 的行为。

cd '/Users/charles/Desktop/天大创业社群/信息层/xuanhuai-platform'

全新副本可运行 `node scripts/prepare-validation.js`：先备份再复制原数据、迁移、导入草稿；已有 `validation-data/` 时拒绝覆盖。这个脚本不监听端口。主目录中的原数据在未来单独启动新版服务时也会自动先备份再迁移；本次没有对运行中的旧服务做这一切换。

## 完整演示

1. 学生浏览器进入课程页，看到本周与下周安排。第 12 周未确认前，固定安排显示“沿用本学期安排，本周待确认”；大讲堂嘉宾、主题、临时教室等未知项留空。问“下周有什么课？”可离线得到本地周表、来源与冲突提示。
2. 用管理员登录教师工作台，创建一个老师账号，在课程归属中把课程指定给该账号。资料主讲人只是分配参考，不会自动建立账号或冒充已联系老师。
3. 老师用自己的账号登录，选择 `2026-11-16`。表内显示全部可见场次，只有自己负责的可以填写。黄色项显示问题，填写后勾选“已核对”；沿用项可直接修改。
4. 点“保存填写并查看发布提案”，核对完整安排、可见范围和仍待确认的字段，再点“确认发布”。只发布本人负责的场次；管理员可处理整周。其他老师未发布的场次继续显示沿用状态。所有场次都发布后周状态为 `published`。
5. 学生关注的是稳定课程，下一周自动延续。老师对已发布场次改时间、换地点或取消时，必须重新提案、确认；关注者在网页打开后 10 秒内刷新通知，其他人不收到。外部 agent 通过工具自行轮询。
6. 新增课程后新增场次；同一门课一周可有多个场次。取消场次保留“已取消”，本学期结课后不再生成后续场次。规则修正、结课均须提案确认。

老师未填写的待确认项不会被一键发布伪造为已确认。暂存的新增内容不会提前进入学生查询；逐字段来源保留沿用依据或提供人、确认时间。

## 导入与规则生成

只读知识库草稿文件，不改知识库、PRD 或客户端。离线命令需在目标数据目录没有另一个写进程时运行；运行中的新实例用工作台/MCP 工具生成草稿。

```bash
XUANHUAI_DATA_DIR="$PWD/validation-data" node scripts/import-draft.js '../knowledge-base/课表/下周课表草稿.json'
XUANHUAI_DATA_DIR="$PWD/validation-data" node scripts/generate-week.js 2026-11-23
```

导入相同文件幂等；同周已有不同内容时拒绝覆盖，改用教师工作台。`rows`、`not_this_week`、`ended`、`unknown` 四组规则、来源和问题一并保存。第 13 周会生成四门有文章依据的单周课：寻找第一个客户、硬科技企业资本力提升之路、在玩耍中学习、AI 驱动的一人公司。四门第 11 周结束的课不会出现。推断或未知规则单列待问，不混入确定生成的场次。

锚点默认：2026 年秋季学期，第 11 周从 `2026-11-09` 开始，可用 `configure_semester` 修改。规则包含起止周、`weekly/odd/even/unknown`、星期、时段、依据和 `inferred`。原资料没有起止周时保留 `null`，不补造。教师确认规则后影响之后生成的周；已存在的周不会自动覆盖，需要单独修改。

## 数据与权限

- `data.json` schema v2：`catalog` 为稳定课程，`weeks[周一日期].sessions` 为每周场次，另存规则、提案、问题、更正建议和变更记录。旧场次 ID 不变，同名课程经标点归一合并；例如旧 `1`、`9` 两个场次同属稳定课程 `1`。`aliases` 保留旧 ID 映射。
- `personal.json`：关注由旧行 ID 迁为稳定课程 ID，重复合并并保留最早通知游标；原令牌摘要、偏好、已读游标和等待关系保留。迁移前若有订阅变化，另备份个人文件。
- `accounts.json`：独立教师账号，口令只存 `node:crypto` scrypt 加盐哈希。管理员仍从 `.local-admin` 读取已有引导口令；此文件是保留的管理员凭据，不是教师账号存储。教师令牌只存内存摘要，有效期 8 小时；重启、登出或重置口令使其失效。
- 旧共享入口变为管理员身份，保留原 `local-teacher` 内部标识以兼容既有合作需求的所有权；该标识不向普通老师授予管理员权限。旧课程中原本由本机教师接收的问题迁为管理员代管；导入的新草稿按实际负责账号分配，未分配时只由管理员看到且保持“已登记待转交”。
- 默认范围 `members`：全体本机已登录成员；`staff`：仅负责老师和管理员。课程和场次范围共同约束查询。详情、课表、汇总、变更、推荐和追问结果均过滤受限内容。匿名课表为空；为兼容既有知识检索/MCP，历史文章搜索和文章目录仍可匿名读取。
- 教师只能改负责课程，对别人负责的课程提交更正建议；建议进入负责老师待处理列表，无负责人由管理员处理。确认时重新检查负责人和版本，旧提案不覆盖新内容。
- 追问支持地点、时间、主讲人、是否开课、报名方式、主题、嘉宾、校区。无课程 ID 时按课程名登记，由管理员分配。草稿问题与学生问题按场次/字段合并，不附学生身份和原话。四级进度：已登记待转交 → 已向负责老师询问 → 已答复待确认 → 已确认。

这是本机验证版：个人会话是本机生成的令牌，**尚未实现 PRD 7.1 的天大邮箱验证和邀请码**；不验证邮箱、不发邮件、不联系外部老师。PRD 7.2 的多 agent 独立令牌管理、长期不活跃自动失效尚未完整实现。没有活动前提醒、邮件周表、自动催办或 A2A。生成草稿是按命令/工具触发的计算，没有新增后台定时生成任务。

JSON 采用原子替换，适用于单 Node 进程本机验证；多实例必须使用不同数据目录。`data.json`、账号、个人数据、验证副本和备份均忽略提交。

## 工具与架构

详见 [AGENT-GUIDE.md](AGENT-GUIDE.md)。新工具通过 `POST /api/tools/call` 和 MCP 共享同一权限检查与业务逻辑。

- `lib/schedule.js`：迁移、日期、规则、课程权限及场次结构。
- `lib/weekly.js`：草稿导入、周次生成、问题归并。
- `lib/accounts.js`：本地教师账号、哈希、令牌、归属管理。
- `lib/public-service.js`：查询、草稿暂存、提案确认、追问、更正建议、汇总。
- `lib/personal-service.js`、`lib/learning.js`：跨周关注、权限过滤后的通知/推荐与追问结果。
- `lib/tools.js`、`server.js`、`mcp.js`：统一 HTTP/MCP 接口。
- `lib/agent.js`：本地课表直接问答与原有模型工具循环。
- `public/app.js`、`public/style.css`：教师周表、账号、规则和提案审核界面。

其他开放式问答仍可选用原 DeepSeek/SiliconFlow 功能：在工作台配置 Key，或设置 `SILICONFLOW_API_KEY`（兼容 `DEEPSEEK_API_KEY`）。Key 只存内存；模型请求会发送相关对话与检索片段。此次开发未调用网络或模型服务。`TEACHER_PASSWORD` 不再作为共享教师入口。
