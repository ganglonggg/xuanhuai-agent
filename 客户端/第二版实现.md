# 第二版：需求发布与意向表达 · 0.5

2026-11-15。对应 PRD 第 10 稿 4.4 节及第二版版本范围。按用户要求提前实现第二版本机功能；第一版连续八周运营、真实课表、学校认证和跨设备部署条件尚未满足，不能将本机验收视为多人正式上线。

## 已实现的流程

1. 老师发布项目需求或导师可约时间：填写可公开简介、希望找谁、能提供什么、合作预期和可见范围。先展示草稿及修改差异，本人核对后发布。
2. 学生对可见需求选择“我想聊聊”：填写我是谁、我做过什么、我能投入多少；确认后才把意向发给需求方。其他学生和无关老师看不到意向卡。
3. 需求方决定愿意继续或暂不继续。拒绝不收集私人理由，对方只看到暂不继续。
4. 双方分别核对并许可交换指定联系方式。单方许可时只看到自己的联系方式和对方许可状态；双方均许可后才显示对方联系方式。
5. 已建立联系后，任一方可提出时间、时长、地点和议题；对方确认后才形成约定。支持重新提出和取消约见。
6. 发布者可以修改、关闭需求；学生可在联系方式交换前撤回意向。修改或关闭会结束尚未建立联系的旧意向；已交换的信息无法收回。

所有写操作都走“准备 → 核对 → 确认”。待确认草稿可恢复、可取消，24 小时过期；确认时重新检查当前权限、状态、可见范围与版本，拒绝旧卡片覆盖新内容。联系与约见内容不会自动发送到微信、邮件或外部日历。

## 客户端入口

- 安装：`/Users/charles/Applications/宣怀 Agent 0.5.app`。退出旧版再打开新版，继续使用原有个人数据目录。
- 工具栏“项目与合作”：默认学生视角。解锁本机教师身份后，可切换老师 / 导师视角。
- 表单不依赖模型，可以完成整个流程；草稿确认页展示发布范围、内容及修改前后的差异。
- 对话整理：解锁后选择输入框模式“老师项目合作”，用自然语言描述需求或可约时间。学生使用普通对话查询需求、准备意向等。模型只能准备卡片，最终按钮由本人确认。
- 需求有“所有已登录成员”和“指定成员”两种可见范围。本机验证阶段使用对方提供的成员标识指定受众，未建设公开个人目录。
- 合作页打开时每五秒刷新；状态未变时不重绘，状态更新时保留滚动位置。已接入合作进度、未读状态和桌面通知；未接入邮件。

## 数据与权限

- `信息层/xuanhuai-platform/lib/cooperation.js` 提供统一业务逻辑；桌面 IPC 和四个 MCP 工具复用同一服务。
- 合作数据位于 `shared/cooperation.json`，文件权限为当前本机用户可读写。它独立于课程公共库，不出现在 `/api/public`、课程查询或文章接口中。
- 需求只返回给可见范围内的登录身份；意向、许可、约见只返回给参与双方；草稿只返回给本人。
- 不存未授权技术原文、个人课表、个人兴趣或拒绝理由。仅保存用户主动提交的结构化卡片、操作草稿、许可和必要状态。联系方式只通过参与者视图返回，单方许可时隐藏对方联系方式。
- 当前本人确认承担发布前的人工核对；没有另设学院管理员复审队列或真实身份审查。
- 桌面支持独立教师账号，管理员可创建账号和重置口令；教师会话、合作草稿和通知按账号隔离。详见《账号整合.md》。
- 文件存储只支持单个服务进程，不提供并发多进程事务。学校认证、服务器数据库、远程接入、备份和数据保留管理仍需在真实试用前完成。

## 验证

行为测试：

```sh
node --test 客户端/test/*.test.js 信息层/xuanhuai-platform/test/*.test.js
```

共 43 项通过，其中新增 9 项合作服务测试和 2 项桌面对话测试。覆盖：

- 发布前不可见、指定成员过滤、跨发布者权限、意向隔离和匿名接口隔离。
- 单方许可不泄露联系方式、拒绝与撤回、需求修改与关闭、旧草稿冲突、重复确认。
- 约见双方确认、重新提议和取消、无效日期、过期草稿、重启恢复。
- 模型生成需求确认卡，锁定教师身份后不能确认；模型不能直接调用确认工具。
- HTTP 工具入口复用相同认证和权限。

原生 Electron UI 流程覆盖第一版功能，以及“发布 → 学生意向 → 继续 → 单方许可仍隐藏 → 双方许可后交换 → 提出约见 → 对方确认”，同时验证 760px 窗口。使用独立临时数据，测试结束删除，不向真实用户发消息。截图在 `test-artifacts/cooperation-*.png`。

## 尚未包含

第三版的 A2A、Agent 自动筛选、多轮匹配、双卡和见后反馈未实现。导师可约时间目前是经确认发布的文字安排，不是自动扣减名额的预约日历。没有真实双人跨设备验收；模型流程用可控模拟响应测试，本轮没有使用真实密钥调用云端模型。

打包后的 0.5.0 应用已用包内代码复跑原生流程并安装。安装包没有携带合作记录或测试账号数据。

## 0.5.3 补充：交换前撤销许可

双方交换联系方式前，可通过确认卡撤销自己的许可，保留合作意向。对方收到不含联系方式的状态提醒；此前准备的旧确认卡失效，需重新核对。交换完成后不提供撤销已披露信息的按钮。历史操作草稿仍保留在本机，因此此操作不等于删除历史数据。
