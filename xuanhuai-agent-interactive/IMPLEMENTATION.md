# 实现说明与接入边界

## 当前架构

原生 HTML / CSS / JavaScript，无框架、CDN、构建运行依赖。index.html 可直接从 file 协议打开；standalone.html 是同版源码的内嵌资源交付。

四个纵向章节：home / discover / week / connect。顶栏和章节导航与滚动位置联动；手机为底部导航。详情、访谈、画像、设置与合作决定采用原生 dialog，内容按需替换，支持关闭、焦点约束与 Escape。

状态分为：界面筛选、公开示例关注、仅当前会话的本人画像、合作任务与授权。示例数据集中在 app.js 的 info / peers，非敏感偏好通过独立版本 key 写入 localStorage，读写失败不会阻塞应用。

## 后续需要替换的服务

1. 访谈：固定问题替换为服务端访谈会话；保存、恢复、错误重试与用户确认返回正式画像版本。
2. 机会：服务端核对、来源链接、时区、取消/改期状态、分页与推荐依据。未知信息不得由浏览器补造。
3. 关注与提醒：真实账号下的幂等写入；后台任务决定提醒是否发送，不依赖前端开关伪装送达。
4. 合作：简报版本、双边意向、授权字段、失效时间由服务端裁决。当前演示按钮只切换本地状态，上线应移除。
5. 画像更新：需要证据引用、字段版本、防冲突检查、范围、期限与撤销审计。不能根据“没匹配上”自动产生永久能力或兴趣结论。
6. 身份：学院账号验证、会话与字段级权限检查均需后端接入；前端隐藏内容不是权限保障。

## 生产前事项

正式学院品牌使用确认；来源核对与法务隐私文案；身份与授权接口；服务端安全验证；错误、取消与过期状态补全；跨浏览器与辅助技术测试；真实慢网与断网测试；用户访谈验证；字体授权与正式部署。

当前只验证了本地前端交互，没有后端、真实邮件、报名或其他外部写入。页面的交互反馈不会假称这些服务已经完成。
